By the end of this page, `testlane` runs from any directory in your shell. It takes a minute with your package manager, and a few more if you'd rather build it from a clone to work on Testlane itself.

## Before you start

Testlane runs on Node.js and shells out to git, so you'll need both:

| Tool                           | Version       | Required                                                                    |
| ------------------------------ | ------------- | --------------------------------------------------------------------------- |
| [Node.js](https://nodejs.org)  | 18 or later   | Yes                                                                         |
| `git`                          | 2.38 or later | Yes                                                                         |
| [`gh`](https://cli.github.com) | Any           | No, though it adds each PR's state and title, `gh pr diff` and push-back    |

Any package manager installs it, and it needs no other runtime. Keep in mind that every feature that uses `gh` falls back to plain git when `gh` is missing or not signed in, so you can add it later.

## Install the CLI

::steps{level="3"}

### Install the package

Testlane is published to npm as `@uxfront/testlane`, and it puts a `testlane` command on your `PATH`. We recommend installing it globally:

:::code-group

```bash [npm]
npm i -g @uxfront/testlane
```

```bash [pnpm]
pnpm add -g @uxfront/testlane
```

```bash [yarn]
yarn global add @uxfront/testlane
```

:::

When it finishes, `testlane` is in your package manager's global `bin` directory.

### Check that your shell finds it

```bash
testlane version
```

It prints the version you installed:

```
testlane 2.0.0
```

If your shell says `testlane: command not found` instead, see [the FAQ](/docs/getting-started/installation#faq) below.

::

## Install from a clone

Install from a clone when you want to work on Testlane itself. It ships as compiled JavaScript, so you build `dist/` before you link it onto your `PATH`:

::steps{level="3"}

### Clone it

```bash
git clone git@github.com:uxfront-com/testlane.git
```

Then move into it with `cd testlane`.

### Build it

Install its dependencies, then compile it:

```bash
npm install
```

```bash
npm run build
```

The build writes `dist/bin/testlane.js`, the file the `testlane` command runs.

### Link it onto your PATH

With pnpm, run `pnpm setup` once first, so pnpm has a global directory to link into. Then link it with your package manager:

:::code-group

```bash [npm]
npm link
```

```bash [pnpm]
pnpm link --global
```

```bash [yarn]
yarn global add "file:$PWD"
```

:::

### Check that it runs

```bash
testlane version
```

It prints your clone's version, like `testlane 2.0.0`.

::

Keep in mind that the linked command runs your clone's compiled `dist/`, not its source. So run `npm run build` again after every `git pull` or change, or the command keeps running the old build.

## Run it without installing

To skip the global step, build the clone and call its entry point with Node:

```bash
npm install && npm run build
node dist/bin/testlane.js version
```

The rest of these docs write `testlane`, so put `node dist/bin/testlane.js` in its place if you haven't linked it.

## Coming from uxd

Testlane was called uxd until 2.0.0. If the old package is still installed, follow [Upgrading from uxd](https://github.com/uxfront-com/testlane#upgrading-from-uxd) in the README to swap it and keep your projects.

## FAQ

::accordion
  :::accordion-item{label="Why does my shell say testlane: command not found?"}
  Because your package manager's global `bin` directory isn't on your `PATH`. Add `$(npm prefix -g)/bin` for npm, `$(pnpm bin -g)` for pnpm or `$(yarn global bin)` for Yarn, then open a new shell.
  :::

  :::accordion-item{label="Do I need Bun or Deno?"}
  No. Testlane runs on Node.js 18 or later, and nothing else.
  :::

  :::accordion-item{label="Can I add gh later?"}
  Yes. Every command that uses `gh` checks for it first, with `gh auth status`, so the commands you run once it's installed and signed in pick it up. Keep in mind that a PR workspace gets push-back only when it's created, so remove one you opened before with `rm` and open it again to get it. Run `testlane doctor` to see whether `gh` is found.
  :::
::
